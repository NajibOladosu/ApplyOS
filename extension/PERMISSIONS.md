# Permission justifications

ApplyOS 1.0.0 was removed from the Chrome Web Store under the **Use of Permissions**
policy (violation reference *Purple Potassium*): the manifest declared
`notifications`, but no code in the package ever called `chrome.notifications`.

This file is the single source of truth for what each permission is for. Paste the
matching sentence into the **Privacy practices** tab of the Developer Dashboard when
resubmitting. `scripts/audit-permissions.mjs` fails the build if any permission here
loses its corresponding API call, so this document cannot drift from the code.

Every permission below is actively used. None are held "for future features".

---

## Permissions

### `activeTab`

**Used by:** `src/popup/tabs/QuickAddTab.tsx`, `src/popup/components/ApplicationDetail.tsx`

Reads the URL and title of the tab the user is looking at, so the popup can prefill a
job it was not written for. Granted only for the current tab, and only after the user
clicks the extension — it is not persistent host access.

Also what lets the popup offer to scan a site ApplyOS has no built-in extractor for.
Because of `activeTab`, the extension does **not** need `<all_urls>`.

### `alarms`

**Used by:** `src/background/service-worker.ts` (`chrome.alarms.create`)

Schedules the hourly reminder sweep. An MV3 service worker is torn down between
events and cannot hold a timer, so this API is the only way to deliver a reminder
that is not triggered by the user opening the popup.

### `notifications`

**Used by:** `src/background/service-worker.ts` (`chrome.notifications.create`)

Delivers two things the user explicitly opts into on the settings page:

1. **Follow-up nudges** — "7 days since you applied to X at Y".
2. **Long-silence alerts** — an application has been waiting long enough that the
   user should decide whether to chase it once more or move on.

This is the permission that caused the 1.0.0 takedown. The feature is now
implemented rather than deleted: the notification text is generated by
`src/lib/reminders/reminder-engine.ts` and surfaced through the sweep above.

### `scripting`

**Used by:** `src/popup/tabs/QuickAddTab.tsx` (`chrome.scripting.executeScript`)

Injects the extraction and autofill bundle into the active tab when the user asks
ApplyOS to read or fill a page it does not already run on. Programmatic injection is
a deliberate choice over a `<all_urls>` content script: the extension is dormant on
every site except the job platforms below until the user asks otherwise.

### `storage`

**Used by:** `src/background/service-worker.ts`, `src/lib/theme.ts`, `src/lib/api/supabase-client.ts`

Persists, on the user's device only:

- the autofill profile and saved answers,
- the Supabase auth session,
- reminder history (so a reminder is shown once, not hourly),
- user preferences.

## Host permissions

These are the job platforms ApplyOS supports directly. Each appears in
`content_scripts.matches`, so a content script is registered for it — nothing here
is declared speculatively.

| Host | Why |
| --- | --- |
| `*.linkedin.com` | Job extraction and application autofill (Quick Apply forms) |
| `*.indeed.com` | Job extraction from `/viewjob` and `/rc/clk` |
| `*.myworkdayjobs.com` | Workday tenant applications (multi-step forms) |
| `*.greenhouse.io` | Greenhouse job boards and embedded application forms |
| `*.lever.co` | Lever postings and application forms |
| `*.glassdoor.com` | Job listings |
| `*.ashbyhq.com` | Ashby-hosted application forms |
| `*.smartrecruiters.com` | SmartRecruiters postings and forms |
| `*.applyos.io`, `applyos.io` | Calls to the ApplyOS API (analysis, cover letters) and the user's account |

### Hosts deliberately *not* requested

- **`<all_urls>` / `*://*/*`** — not needed. Built-in support covers the platforms
  above; anything else is a one-off the user initiates, which `activeTab` covers.
- **`tabs`** — not needed. The four sensitive tab properties (`url`, `pendingUrl`,
  `title`, `favIconUrl`) are only ever read on the active tab, which `activeTab`
  already grants. Requesting `tabs` would widen access to every tab for no benefit.
- **`cookies`, `history`, `bookmarks`, `webRequest`, `downloads`, `geolocation`,
  `clipboardRead`** — none are used anywhere in the codebase.

## Verifying this document

```sh
cd extension
npm run audit      # every permission must resolve to a matching API call
npm test           # includes reminder-engine behaviour, which drives notifications
```

The audit is wired into `npm run build`, so a build that declares an unused
permission cannot be produced.
